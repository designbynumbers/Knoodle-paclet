# KnoodleProve

Reference material for `Documentation/English/ReferencePages/Symbols/KnoodleProve.nb`
(generated by `ci/docs/gen-knoodleprove-nb.wls`). Added 2026-11-12. The
paclet is built on Knoodle 1.2.1; 1.2.0 was the first release whose tools
include `knoodleprove`.

## What it does

`KnoodleProve[trace]` checks a *move trace*: the record a simplifier writes of
the moves it made on a knot or link diagram. A trace holds the diagram the
simplifier started from and, for each move, the move and the diagram it left.
The format is Knoodle's `docs/move-descriptor.md`.

The work is done by Knoodle's `knoodleprove`. It checks every claim in the
trace that does not depend on a drawing:

- each move is well formed against its diagram;
- the move produces the next record's diagram;
- the pieces a move frees are the ones the trace names;
- a middle pass's feasibility witness holds (V0, V4, and V2/V3/V5).

When the trace ends at the empty diagram, the last claim is about the whole
trace. If every move is sound, every link between records is VERIFIED, and
each input component came free exactly once, the input is an unlink: for a
knot, the unknot.

Move kinds checked: pass, middlepass, r1 (curl removal) and redraw. A move of
any other kind is reported UNCHECKED, never skipped. A record marked
`#candidate` is a move the simplifier evaluated but did not make: its claims
are checked, but it is not part of the proof.

The claims that do depend on a drawing (that the pictures of a move show the
right diagrams) belong to `knoodledraw --trace --verify`. The paclet does not
wrap that.

**Where traces come from.** Nothing in Knoodle writes a trace yet. The ones
bundled in `Resources/ExampleData/Traces` (asset `"ExampleTraces"`) were
recorded by the *middlestrands* project's simplifier, which is built on
Knoodle. They are copies of Knoodle's `test/*.trace` fixtures (the same in
v1.2.0 and v1.2.1); the README there says what each one is.

## Calling convention

```
KnoodleProve[trace]
KnoodleProve[trace, "CheckExterior" -> True]
```

`trace` is one of:

- `File[path]`;
- a path given as a string;
- the trace's text, as a string.

A string with no line break that names an existing file is read as a path.
Any other string is the trace itself, since a trace always runs to several
lines.

## Return value

An `Association`:

| Key | Value |
|---|---|
| `"Verdict"` | `"VERIFIED"` if every claim checked out, `"MISMATCH"` if any claim is false, `"UNCHECKED"` if none is false but some could not be checked |
| `"Unlink"` | `True` when the trace's whole-trace `unlink` claim is VERIFIED |
| `"Claims"` | one `Association` per `#verify` line, in order: `"Step"` (the record number, or `All` for the whole-trace claim), `"Claim"`, `"Verdict"`, `"Detail"` |

A line that only reports, `split` (which components a move freed), has
`"Verdict" -> None`.

Claim names come straight from knoodleprove. They include:

- `pd`, `descriptor`, `result`, `colors`, `trace`, `split`, `spinoffs`;
- `r1`;
- `redraw`, `projection`, `rotated`;
- `disk (V0)`, `classes (V4)`, `labels (V2/V3/V5)`;
- `exterior` (with `"CheckExterior"`);
- `unlink`.

`"Detail"` is knoodleprove's own text. The surrounding `( )` or `-- ` is
removed, and nested parentheses are matched. A MISMATCH line can carry both
forms, `(…) -- …`, and that one is kept as it is.

## Failures

knoodleprove exits 1 on any MISMATCH, on a malformed stream, and on a library
error. The wrapper separates these cases:

| Situation | Result |
|---|---|
| exit 0 | the Association |
| exit 1, a MISMATCH line on stdout, nothing but `knoodleprove: warning:` lines on stderr | the Association, with `"Verdict" -> "MISMATCH"`, and no message: a false claim is an answer |
| any other nonzero exit (malformed stream, missing file, library error) | `$Failed` and `KnoodleProve::knoodletool`, quoting the tool's last stderr lines (e.g. `knoodleprove: <stdin>: trace line 3: bad PD entry 'not'`) |
| exit 0 with no `#verify` lines (an empty stream) | `$Failed` and `KnoodleProve::norecords` |
| `trace` is not a File or string | `$Failed` and `KnoodleProve::badinput` |
| `"CheckExterior"` not `True`/`False` | `$Failed` and `KnoodleProve::badopt` |

## Options

| Option | Default | Meaning |
|---|---|---|
| `"CheckExterior"` | `False` | Pass `--check-exterior`: also check each record's `#view` claim, that its exterior face is the image of the previous one's across the move, with `outside=`/`behind` as the rule requires. Records without a `#view` come back `exterior: UNCHECKED (no '#view')`, so a trace with no views turns `"Verdict"` to `"UNCHECKED"`. |

Not exposed:

- `--thread-exterior` rewrites the stream, choosing an exterior face for each
  record. It does not check anything. It feeds the animator, which the paclet
  does not wrap.
- `--version`: the paclet's tool build passes no version macro, so it prints
  `knoodleprove unknown`.

## Examples on the reference page

All examples use the bundled traces:

- `pass_lasso`: VERIFIED and an unlink. The page shows the claim table and
  the first 19 lines of the trace's text.
- The same text with one crossing changed (`C_state = {-1,-1,1}` becomes
  `{-1,-1,-1}`). The diagram alternates, so it is a trefoil. The result is
  `descriptor: MISMATCH -- … the strand passes over at some of its interior
  crossings and under at others, so it is not a pass move at all`, and
  `unlink: UNCHECKED`.

  The trefoil was checked by hand in Knoodle's convention: the under-strand
  enters at (In,Right) at a right-handed crossing and at (In,Left) at a
  left-handed one. The original reads U U U O O O along the knot, and the
  changed one reads U O U O U O.
- `fhw_unlink`: the Freedman–He–Wang 32-crossing unknot, with 15 moves, is an
  unlink.
- `middlepass_unlink`: the witness claims of record 5 (record 4 is the same
  move as a candidate).
- `redraw_link_example`: VERIFIED, and `"Unlink" -> False`.
- `exterior_sticky_example`: VERIFIED except one UNCHECKED `trace` (its last
  record has nothing after it). With `"CheckExterior" -> True`, four of its
  six views are MISMATCH.
- A malformed string: `$Failed`.

Long details are shown with `Grid[..., ItemSize -> …]` or as an
Association, not in a `Dataset`, which clips them.
